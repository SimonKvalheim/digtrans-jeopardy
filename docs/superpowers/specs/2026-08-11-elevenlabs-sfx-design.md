# Generated sound effects — design

**Date:** 2026-08-11 (event day) · **Status:** implemented · **PRD:** §8.3

Replaces the board's eleven synthesised stings with sound effects generated by
ElevenLabs, without giving up the property that made the oscillators safe.

## What this is not

**Music was cut.** The original scope included a Final Jeopardy think cue, a
lobby bed, an opening theme and podium music. The ElevenLabs Music API returns
`402 paid_plan_required` on a free account, and the sound-effects endpoint —
which is available — caps at 30 seconds, so a 60-second Final cue could not be
produced in one piece regardless. §8.3's music line is therefore still open.

**The host voice (§8.2) is untouched.** `clue_media.ttsBytes` remains unused.

## Constraints this had to hold

| Non-negotiable | How |
|---|---|
| Nothing third-party on the critical path at play time | ElevenLabs is called only by a laptop script. The server and board read bytes from our own Postgres. |
| Content never enters git | Audio lands in the already-gitignored `media/`. Only prompts are committed — they describe noises, not answers. |
| Playable as it was before | Purely additive. An empty table is byte-for-byte the previous behaviour. |

## Design

### Storage — `show_media`

```
name  text pk   -- one of STING_NAMES
bytes bytea     mime text        gain real default 1
prompt text     durationMs int   generatedAt timestamptz
```

Not hung off `packs` or `games`. Unlike `clue_media`, these are app furniture:
identical every night, and they must survive a pack re-import. One additive
`CREATE TABLE` (`drizzle/0006_swift_gravity.sql`); nothing existing is altered,
which is what made it safe to migrate at boot on the day.

`gain` is in the database rather than baked into the mp3 so the mix stays
tunable against the actual TV without regenerating or redeploying.

### Serving

- `GET /api/media/show` — manifest of `{name, gain, generatedAt}`, `no-store`.
- `GET /api/media/show/:name` — bytes, with the ETag/`must-revalidate` pattern
  already used for clue images.

Both unauthenticated, like the rest of the board's read path. A buzzer is not a
secret. Declared before the `/:gameClueId` routes so `show` is never parsed as a
uuid.

### Playback — two layers, oscillator underneath

`unlockAudio()` starts a **non-blocking** load: manifest → parallel fetches →
`decodeAudioData` into a `Map<StingName, AudioBuffer>`. The tap never waits on
it; going fullscreen must not stall behind a network request.

```
sting(name) → buffer loaded? yes → BufferSourceNode → gain → master
                             no  → STINGS[name]()   (the oscillator)
```

Every failure — empty table, dead venue network, a clip still in flight when the
first buzz lands, one corrupt row — degrades to the game as it sounded before.
`STINGS` is typed `Record<StingName, () => void>`, so adding a name without a
fallback is a compile error rather than a silent hole.

Decoding happens up front because the first sound of an evening is usually a
buzz, and that is the one moment where late is worse than synthesised.

### Generation — `pnpm sfx`

```bash
pnpm sfx                  # generate whatever is missing
pnpm sfx buzz winner      # re-roll by name
pnpm sfx --process        # re-trim/re-level from raw — costs no credits
pnpm sfx --list           # what is on disk
pnpm sfx --upload         # push media/sfx into the app
```

Generate → **listen** → re-roll → upload. That loop is the reason for
pre-generating at all, and mirrors §8.2's "listen to all 60 in advance".

Raw downloads are kept beside the processed files so changing the filter chain
never costs another generation. ffmpeg trims any leading silence and
peak-normalises to −1 dBFS; the per-sting mix is applied at playback via `gain`.

### Admin

`PUT` / `GET` / `DELETE /api/admin/show-media/:name`, behind `ADMIN_PIN`,
mirroring the clue-image trio. `DELETE` is the rollback: one call reverts one
sound to its oscillator, mid-evening, no redeploy.

## Decisions worth recording

**Names are validated against a shared list.** `src/shared/stings.ts` is the one
source of truth, imported by the board, both route files and the script. A clip
filed under a name nothing plays would be silent with no error anywhere — the
worst failure this table can have — so it is rejected at upload.

**The mix is not flat.** Peak normalisation gets all eleven to one baseline,
which is not the same as a mix. Played flat, the countdown tick — which fires
five times in a row — arrives as loud as the buzzer. The `MIX` table in the
script carries the ratios from the oscillator gains, which were tuned by ear
against a room: buzzer at 1.0, tick at 0.3.

**`tick` got a generated clip despite the recommendation against it.** A 35 ms
click is a case where synthesis is genuinely better than a file. Deleting the
row reverts it, so the choice is cheap to undo after the dry run.

## Bug found during implementation

`peakDb()` first read `execFileSync`'s stdout, but ffmpeg writes `volumedetect`
to **stderr** and exits 0 — so it parsed to `null`, every gain became `0 dB`,
and normalisation silently never ran. Invisible on ten of the eleven clips,
which ElevenLabs returns near 0 dBFS anyway; `tick` came back at **−26.8 dB**
and would have been inaudible in a loud room. Fixed by reading stderr via
`spawnSync`. Re-processing then moved `tick` by +25.8 dB.

## Verified

- `pnpm typecheck`, `pnpm test` (12/12), `pnpm build` — all pass.
- All eleven generated: 201 credits total, peaks now −1.1…0.0 dBFS.
- No leading silence in any clip, so the buzzer starts on the first sample.
- Routes smoke-tested without a database: `/show/:name` correctly rejects an
  unknown name with 404 (proving it is not swallowed by `/:gameClueId/image`);
  admin PUT returns 401 on a wrong PIN, 400 on a bad name, missing body, or
  empty bytes.

## Not verified

Nothing has been deployed, and no clip has been played through the board or
listened to. Both need the dry run.
